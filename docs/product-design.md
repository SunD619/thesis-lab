# 产品设计与取舍

## 目标与核心体验

用户已经有观点，但需要知道它是否经得起反证。产品将“我要验证一个判断”作为入口，避免退化成泛泛的财经聊天。

主链路：输入命题 → 澄清研究对象与口径 → 用户修订确认 → 核对利润前提 → 取财务与年报证据 → 显示有限结论、冲突、未知和改判条件 → 追问/保存。

## 用一个案例说明价值

输入“五粮液2024年利润增长主要来自主营业务改善，盈利质量同步提升”。利润增长是可验证事实；酒类收入和毛利改善提供支持线索；非经常性损益明细帮助排除一次性因素主导；经营现金流下降则让“质量同步提升”遇到反证。用户获得的不是简单赞同，而是知道命题哪一部分有依据、哪一部分需要收窄。

数值与文字必须回到证据详情：接口字段/计算式，或年报原文/页码。模型判断与原始材料分开呈现。

## MVP 为什么这样切

| 选择 | 理由 | 代价 |
|---|---|---|
| 两家公司、年度盈利质量 | 时间有限，先验证研究闭环与口径 | 不支持任意股票和宏观命题 |
| 四个固定研究问题 + AI 澄清 | 问题可解释、可测试，降低随意拆解 | 暂未实现通用动态研究规划 |
| 精选原文库 + 条件筛选 | 少量可靠材料比未验证的大库更便于追溯 | 召回范围有限，必须展示缺口 |
| Vue + FastAPI 单服务 | 减少部署环节，后端保护凭证 | 没有独立任务队列或多实例会话 |
| 浏览器保存、JSON 导出 | 满足回看研究的核心需要 | 不跨设备，追问记录尚未导出 |
| 文本模型 hy3 | 输入为结构化字段与文字摘录 | 扫描版年报需以后增加 OCR |

## 证据与 AI 分工

确定性程序负责接口鉴权、日期/公司筛选、同比和毛利率、空值、缓存、引用编号与输出结构。模型负责澄清语言、解释证据关系、寻找反证、提出尚待核验的问题。

服务端只验证引用是否存在，不能自动证明每句话被该引用支持。开发中观察到了过度归因；因此加强提示词、显式列未知项、降低完全因果结论，并保留原文供人工复核。对“公司未披露”的特定措辞收窄成“当前材料未覆盖”，不改动证据原文。

## 如何判断产品有效

先做小样本人工评估，不用本轮三例推导准确率：

- 用户是否能完成修订命题并获得完整结果；是否能找到对应原文。
- 模型是否先检验命题前提；是否主动列出关键反证。
- 每条关键判断是否具有相关证据，而不只是一个存在的编号。
- 数据不足或接口失败时，是否准确说明不能判断的范围。
- 后续计划记录端到端耗时、主链路完成率、引用语义准确率、过度归因率和失败恢复率；目前未进行用户实验和统计评测。

P1：接入 iFinD 公告检索，按问题检索更多原文，补税费/费用和现金流明细，做引用语义评测。自动化计算利润变动桥接，减少模型心算。

P2：扩大行业与公司，支持动态子问题、版本对比、账户保存和证据更新提醒。需先解决口径治理与评估，不能仅靠增加工具数来宣称能力提升。
