# AI 使用与验证记录

日期：2026-10-13。记录真实开发过程，未宣称每条输出都经过独立金融专家复核。

## 开发中的 AI

使用 Codex 协助需求收敛、接口调试、前后端实现、测试、文档和浏览器验收。候选人提供题目、交付时间、技术背景、可用凭证，并决定先完成本地版本。没有使用子代理并行开发。

## 产品运行时的 AI

腾讯云 TokenHub `hy3`，文本输入，OpenAI 兼容 Chat Completions，`reasoning_effort=none`，JSON 输出。没有调用多模态模型。三个调用点：命题澄清、证据分析、基于本次证据的追问。后端发送用户研究文本、公开财务字段和年报摘录；API 密钥通过鉴权头发送到各自服务，不进入模型提示词或浏览器。

输入与输出约束实现在 `backend/main.py`。程序先提供证据编号、原值/计算结果、问题编号和缺失项，再要求模型输出支持、反对、未知、冲突及改判条件。服务端使用 Pydantic 校验结构，并拒绝不存在的引用或不完整的问题编号集合。

## 观察到的问题及修正

| 观察 | 修正 | 剩余限制 |
|---|---|---|
| 初次分析把利润增长等同于主营改善 | 要求先核对前提，区分扣非与主营，收窄因果结论 | 仍需人工检查语义 |
| 回答内容与 Q3/Q4 标题错位 | 将四个问题的编号和内容完整传入模型 | 编号校验不等于语义校验 |
| 说“公司未解释”，实际仅是语料没有覆盖 | 提示词明确有限语料边界，并对特定缺失断言收窄措辞 | 无法覆盖所有语言变体 |
| 追问将应收/应付等可能原因当成事实 | 加强追问证据约束，传入本次结论与未知项，区分事实和假设 | 不是自动事实核查系统 |
| 容易把现金流下降直接等同于质量变差 | 明确区分增速、现金覆盖和质量判断 | 需更多现金流业务解释材料 |
| 模型可能引用不存在编号 | 服务端拦截并显示错误，保留已有证据 | 引用存在不保证引用相关 |

## 人工与程序验证

- 接口：实际鉴权测试扶摇与 TokenHub；检查 HTTP 与业务 code。
- 数值：程序计算同比；对照公开年报检查关键财务值；渲染 PDF 页核对表格。
- 功能：真实浏览器操作输入、澄清、验证、证据详情、追问、保存、刷新回看和导出。
- 异常：自动化模拟接口不可用、模型错误、缺值、错误引用和失效会话。
- 成本：初始三次试调用 971 tokens；后续完整链路有额外调用，不把初始数值当累计账单。产品结果保留接口返回的模型用量和耗时。未查询账户计费余额。

详见 `integration-test.md` 与 `test-report.md`。原始调试响应只在本地 `.local/` 保留，不提交密钥与完整私有调试目录。
