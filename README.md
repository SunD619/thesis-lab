# 证见 · THESIS LAB

将一个投资判断，变成可以核验、追问和修订的研究记录。

本项目对应「投资命题与多证据验证」。当前为可操作的本地 MVP，使用真实扶摇财务接口、腾讯云 TokenHub `hy3` 和公开年报片段。**尚未部署公网，公网 URL、仓库链接与演示视频待补齐。**

## 本地体验

当前电脑已安装依赖、配置密钥并构建前端。打开终端运行：

```powershell
cd D:\同花顺AI笔试
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

访问 http://127.0.0.1:8000 。终端关闭后服务停止；端口已运行时无需重复启动。

推荐路径：默认五粮液 2024 命题 → 拆解并澄清 → 确认或修订命题 → 开始验证 → 查看四个问题和正反证据 → 点 D3 核对年报页码 → 追问 → 保存研究。

### 体验用例：把模糊命题澄清为可验证命题

当前已有“AI 建议改写 + 待确认口径 + 用户修订确认”功能，无需新增功能即可体验。它不是多轮问答式澄清，也不会自动知道用户所说的“最近”究竟指哪段时间。

1. 点击「新建验证」，公司选择「五粮液」，报告期选择「2024 年报」。这是用户为本次研究选定的范围，并不意味着 2024 年是当前最新年度。
2. 将命题替换为：**五粮液最近利润涨了，主要是主业带动的。**
3. 点击「拆解并澄清命题」，查看 AI 建议表述与待确认口径。

2026-10-13 对现有 `/api/plan` 的一次真实 hy3 调用返回：

> 五粮液2024年归母净利润同比增长，且增长主要由主营业务（酒类销售等核心业务）驱动，而非非经常性损益。

同时列出三个待确认假设：

- 利润口径为归母净利润。
- “最近”指2024年而非其他时段。
- 主业指酒类核心业务而非投资等副业。

这一步只是把原来的判断写清楚，**还没有证明利润确实增长，也没有证明其原因**。模型每次措辞可能不同；新增的“而非非经常性损益”等限定也需要用户确认是否符合原意。

4. 如果建议符合原意，点击「采用此表述」；也可以直接在「本次确认命题」中修订。例如进一步明确比较基期：

   > 五粮液2024年归母净利润较2023年增长，且增长主要由主营业务改善带动，而非非经常性损益增加。

5. 如果不认同年份，点击「返回修改公司 / 年份」重新选择；如果不认同利润口径或主业定义，先修改命题。当前四问框架主要围绕归母净利润，不保证其他利润口径可直接验证。
6. 点击「确认，开始验证」，此时才开始取数核验，包括检查“利润增长”这个前提是否成立。

**观察重点**：“最近”“利润”“主业”从模糊表述变为明确的待确认口径；用户可以接受或修订，随后进入证据验证。页面中的口径提示是 AI 假设，不代表用户已经逐项确认。

**已知限制**：另一条更宽泛的输入“五粮液最近盈利好像变好了，应该是主业做得更好了。”在本轮测试中被模型改写成“盈利质量”改善，存在概念混用。因此当前功能是辅助澄清，不能保证自动消除所有歧义；必须阅读并修订建议，不能直接把 AI 改写视为可靠定义。此次仅补充用例和说明，未修改产品逻辑。

## 面向谁，解决什么

面向有初步投资观点、愿意阅读财报但不善于组织证据的个人研究者。核心问题是：容易把“利润增长”直接当成“主营改善”，或者只寻找支持自己观点的材料。

当前切入两家白酒公司的年度盈利质量：五粮液、贵州茅台，2024 / 2025 年。选择同一行业便于控制口径、验证正反案例；不宣称覆盖全市场或所有投资命题。

## 设计与 AI 角色

1. **澄清**：AI 补齐公司、年度、利润口径；用户可修订并确认。四个子问题采用盈利质量研究框架：利润前提、主营收入与毛利、非经常性损益、经营现金流。
2. **取证**：服务端调用真实年度利润表与现金流量表。按公司、年份筛选预先核验的公开年报片段。
3. **验证**：程序计算同比和毛利率；AI 根据证据组织支持、反对、未知、冲突与改判条件。结构与引用编号通过校验后才展示结论。
4. **继续研究**：依据同一证据集追问，或保存到当前浏览器、导出 JSON 研究文件。

AI 不负责获取凭证、执行任意工具、补造缺失数据或决定交易。没有虚构置信分数，不用证据条数投票。引用存在性校验不能保证语义完全正确；原始字段、原文和页码供使用者复核。

## 数据与口径

| 数据 | 实际来源 | 使用方法 |
|---|---|---|
| 营业收入、归母净利润、营业成本 | 扶摇年度合并利润表 | 取本期/上期原始字段，程序计算 |
| 经营现金流净额 | 扶摇年度合并现金流量表 | 比较同期变化，不能直接归因于回款 |
| 扣非、非经常性损益、酒类业务与现金流说明 | 公司公开年报 | 保存原文摘录、链接、PDF 页码、披露/核验日期 |

- 缺值不是零；上期≤0或缺失不计算普通同比。
- 综合毛利率不是酒类分部毛利率；扣非净利润不是主营业务利润。
- API 数据与公司年报可能同源；派生指标不是新独立证据。
- API 缓存 6 小时，并显示实际获取时间。当前使用最新可得材料回看历史年度，**不是历史时点回测**。
- 五粮液 2024 年原文已覆盖；五粮液 2025 年暂缺整理的原文，会显示缺口。贵州茅台 2024 的部分对比数据来自 2025 年报，在来源中明确标示。
- 原始材料：[五粮液 2024 年报](https://static.cninfo.com.cn/finalpage/2025-04-26/1223311527.PDF)、[贵州茅台 2025 年报](https://pdf.dfcfw.com/pdf/H2_AN202604161821275610_1.pdf)。
- iFinD 尚未接入。本项目不将其列为已实现数据来源。

这是针对有限语料的证据检索与生成流程，没有部署向量数据库，也不是通用公告搜索引擎。

## 从源码安装

需要 Python 3.12+、Node.js 22+。Windows：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
Copy-Item .env.example .env
```

编辑 `.env` 填入 `FUYAO_API_KEY` 与 `TOKENHUB_API_KEY`，然后运行 `start.ps1`。已有 `.env` 时不要覆盖它。密钥只在后端使用，禁止写入前端代码、仓库或录屏。

前端开发可运行 `npm.cmd --prefix frontend run dev`；Vite 将 `/api` 代理到本地 8000。后端单独启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

验证命令：

```powershell
.\.venv\Scripts\python.exe -m pip install pytest
.\.venv\Scripts\python.exe -m pytest tests -q
npm.cmd --prefix frontend run build
```

## 结构与接口

```text
frontend/src/App.vue       交互流程、研究档案、证据详情与追问
frontend/src/style.css     桌面与移动端布局
backend/main.py           取数、计算、模型、引用校验、流式状态接口
backend/data/documents.json  已核对的原文证据
tests/test_core.py        计算、引用、异常、边界测试
docs/                    产品说明、测试、AI 使用记录、演示脚本
```

`GET /api/health` 配置状态；`GET /api/catalog` 覆盖范围；`POST /api/plan` 澄清；`POST /api/research` NDJSON 阶段/证据/结果流；`POST /api/followup` 基于研究会话追问。生产构建由 FastAPI 同源提供静态页面，无需分别部署前后端。

## 边界与未做事项

- 不预测涨跌，不输出买卖指令。输入规则只是基础防护，不是完备的金融合规系统。
- 原文库只覆盖精选年报，不提供全市场、研报、新闻或实时检索；没有向量索引。
- 没有账号、多设备同步、多人协作、定时监控或自动交易。
- 研究存于浏览器（最多 20 条）；追问会话存于服务进程（最多 100 条、2 小时），重启后需重新验证。保存和导出目前只包括报告及证据，不包含追问对话。
- 接口超时、模型格式/引用异常会明确提示。不会用演示数据伪装真实结果。模型仍可能误读原文或过度归因，需回查来源。
- `Dockerfile` 与 `render.yaml` 是待验证的部署配置。本地版本已构建验证，但当前电脑未进行 Docker/云端运行验收。公开部署前需补充访问保护、额度限制及公网回归测试。
